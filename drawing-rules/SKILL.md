# 附图规则与出图检查（v0.1.6 候选）

一句话：输入申请类型与技术领域 → 输出图件规划（建议模式）、附图规范检查结论、GPT 出图 prompt 约束与 QC 报告、附图相关 OA 修改风险评估（草稿+依据+人工复核点）。

## 触发条件

撰写/审计/提交/OA 阶段涉及附图决策、附图制作、附图检查或附图相关修改时。

## 任务类型门槛（v0.1.5·A312-08 新增）

**按**请求类型**确定必需节点与完成条件——不是所有请求都要先拿到一张合格新图。**

| 请求类型 | 必需节点 | 完成条件（可交付时点） | 图件放行 |
|---|---|---|---|
| **规划型**（"应有哪些图"、"要不要附图"、"配什么图件"） | 节点1、节点2 | 产出**有依据的图件规划建议**（标注策略性质/可推翻性） | 不适用（本轮不产出候选图） |
| **诊断型**（"当前有哪些错误"、"检查一下附图规范"） | 节点1、节点4（规范检查部分）、节点5 | 产出**问题报告**（含"不通过"结论）——**报告 QC 失败不受阻** | 不适用 |
| **出图型**（"帮我出图"、"生成附图"） | 节点1、2、3、4、5 | 节点3 结果过节点4 复核门；**候选图未过 QC 不得进入后续提交** | **候选图进入提交**受 QC 门约束 |
| **OA 修改型**（"这张图能不能用来改权利要求"） | 节点1、节点5（OA 分支） | 产出**修改风险草稿 + 原始公开依据表 + 人工复核点** | 不适用 |

> **关键区分（A312-08 验收）**：「QC 失败不得放行」约束的是**候选图进入后续提交**，**不阻止**本 Skill 输出一份 QC **失败**报告；连接/规范错误可正常输出「不通过」结论。
> **护栏不得退化为全部阻断**：仅请求规划或检查时，不因"尚无合格新图"而拒绝交付诊断结果。

## 最小执行结构

```
输入（申请类型 INV/UM/DES/PCT + 技术领域 + 现有图件清单 + 请求类型）
 → 节点1 必要性判定【规划/诊断/出图/OA 均必需】
 → 节点2 图件规划（领域建议集·建议模式，可被交底内容推翻）【规划/出图必需】
 → 节点3 制图/出图约束（人工制图 或 GPT 出图两分支）【出图必需】
 → 节点4 规范检查 + GPT QC + 人工复核门【诊断必含规范检查；出图必含 QC+复核门】
 → 节点5 汇总检查（附图说明覆盖/摘要附图/缺图阻断/OA 风险）【诊断/出图/OA 必需】
 → 输出分栏：材料读取状态 ｜ 知识依据状态 ｜ 检查结论 ｜ 产物可使用程度
 → 交付：完整 / 部分（列缺口）/ 阻塞（列缺什么怎么补）
```
- 节点依赖：1→2→3→4→5 顺序执行；节点3 仅在需出图时进入，其结果必须过节点4 复核门。
- 多条件同时满足（如既缺图又有标记不一致）：先处理阻断级（节点5 阻断项），再处理标记级。
- 动作冲突（如补图 vs 删文）：呈现两条路径及申请日风险，交人工选择。
- 完成判定：**按上表任务类型**取必需节点的完成条件；任一必需节点存在未知 → 部分（未知向后传播至此）。
- 〔执行约定依据：KE-DRW-026 r3（内部约定，内部决策记录见条目）〕

## 输入四态处理（v0.1.5·拆分）

| 输入情况 | 处理 |
|---|---|
| **未提供**（用户没给，如未给图像/权利要求文本） | 对应结论=**未能核查**（非「符合」非「不符合」），列入缺口与索取清单 |
| **未读取**（提供了但本 Skill 未实际读取/读取失败） | 同上=未能核查，并注明「已提供未读取」以区别于未提供 |
| **不可读**（提供了但格式/权限导致无法解析） | 同上=未能核查，注明不可读原因（**不得**降级为「未提供」） |
| **确实不存在**（经核查确认实际没有，如经核对确无附图） | 按规则判定（如 UM 无结构附图→阻断） |
| **只有名称/清单、无实际图像** | 视觉相关结论（图中文字、标号、关系）=**未能核查**；不得把「没收到图像」解释成「实际没有图」 |

## 输出分栏（v0.1.5·A312-08 新增）

每次交付按四栏并列，不混写：
1. **材料读取状态**——哪些输入已读、未读、不可读、确实不存在；
2. **知识依据状态**——本次结论所依据的条目及其资格（可执行/建议/预览/仅预览）与未知项；
3. **检查结论**——按节点输出（可含「不通过」「未能核查」）；
4. **产物可使用程度**——候选图是否放行提交；报告本身可交付（含报告不通过）。

| GPT 出图 QC | 生成候选图（**四维度分别判定**） | ①对象：漏画/增画→不满足；②数量/标记：错标号/标号集合不对称→不满足；③语义关系（**六类：位置／连接／方向／顺序／运动／信号**）与输入不符→关系漂移→不满足须重绘；**排版豁免仅限位置类**（画布重排／避让遮挡移动／缩放平移／图面尺寸变化不构成位置类漂移），其余五类不豁免；④证据可读性：图不可读/未提供图像→未能核查 | QC 报告（四维度分列）+人工复核，**候选图**不得直接提交 | KE-DRW-020 r2 / KE-DRW-029 r3 / KE-DRW-030 r3（内部约定可执行） |

> 节点模式由绑定条目资格派生，派生结果是 **mode ceiling（最大模式）**——待核验→预览；允许解释性展示→建议；允许执行使用→可执行；候选→仅预览。**use／scope／required deps／unknown 只能把它降级，不得升级**（必要依赖缺失或未知 → 该结论=未知，落到更弱模式；用途越权 → QUAL-USE 直接拒绝）。ceiling 由 validator 独立重算验证（机检口径：绑定 mode **不得强于** ceiling），**不得从产品表格反推条目已获准**。业务上暂不执行某节点可以是系统正确处理的结果，不以功能放行比例作质量评分。
> **用途准入（v0.1.5）**：`use` 字段参与准入判定——绑定若声明超出条目资格的用途（例如把内部约定条目用于「已核实外部法律事实的最终结论」），验证器 **QUAL-USE** 直接拒绝；**「可执行」不等于全用途授权**。

## 依赖作用域与未决状态消费（v0.1.6·WP-6 新增；运行期强制）

**本节把条目 `ke-meta` 的 `deps[].claim_scope` 与 `open_layer` 从「记录级声明」提升为「运行期消费契约」**——本 Skill 取用某条 KE 时，必须按**子命题作用域**取用，不得把整条记录当作不可分割的整体。

### 消费规则

| 规则 | 内容 | 违反的后果 |
|---|---|---|
| **RC-1 子命题级作用域** | `required=true` 的依赖**只作用于**其 `claim_scope` 列出的子命题；未列出的子命题不受该依赖影响。**不得**把子命题级依赖扩大到整条记录 | 该结论降级为「未知」 |
| **RC-2 未知的局部性** | 某必要依赖缺失／不可用 → **仅**其作用域内子命题=**未知**；其余子命题**保持原状态**；**不得**因一个子命题未知而把整条记录判为失效 | 越界结论视为越权 |
| **RC-3 记录级须显式标注** | `deps[]` **不含** `claim_scope` 键 = **记录级**（作用于整条记录）；此时输出**必须**标注「作用域=记录级」，**不得**默默当作子命题级 | 缺标注 = 未按契约消费 |
| **RC-4 未决状态传递** | 所绑定条目 `open_layer.status = unresolved` 时，输出**必须原样携带**：未决状态、**全部**候选、`internal_decision_scope`；采用某一候选时标签**只能是**「本工具链内部策略」 | 覆盖／抹除／改标签 = 违反 WP-6 |
| **RC-5 候选不得作默认依据** | `open_layer.candidates` 中任一项**不得**作为默认执行依据；只请求某子命题时，**不得**以未决层候选替代该子命题自身依据 | 越界执行 |
| **RC-6 非法作用域一律拒绝** | `claim_scope` 为空数组／非数组／含未注册 ID → **整条消费被阻断**（契约 `invalid_scope_effect`）：**不得**继续给出该记录的结论，**不得**静默降级为记录级，**不得**只跳过那一条依赖而照常输出其余子命题 | 静默接受／只跳过一条 = 契约失效 |

> **与节点绑定表的关系**：绑定表回答「用哪条 KE」，本节回答「用**这条 KE 的哪个子命题**」；两者缺一不可。绑定表的 mode ceiling **不得**因本节规则而被提升。
> **本条实例（KE-DRW-025 r6）**：`C01`（来源许可）／`C02`（生成规则）／`C03`（本轮设计候选·仅预览）各自有独立的必要依赖与证据强度；`open_layer`（「额外」修饰范围）为 `unresolved`，两个候选必须原样传递。
